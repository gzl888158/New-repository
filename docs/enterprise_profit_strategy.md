# 企业级盈利策略设计方案（针对个人使用）

> 版本 v0.1（评审稿）｜日期 2026-08-17
> 状态：待评审，确认后再进入代码实现。
> 结论先行：**系统的"工程"已经是企业级，但"alpha"不是。本方案不做加法堆策略，而是做减法——把磨损型高频网格收敛为"regime 门控 + 低频高置信 + 正期望白名单"的核心引擎。**

### 1.1 近 7 天策略贡献

| 策略 | 盈亏(USDT) | 笔数 | 胜率 | profit factor | 健康度 | 结论 |
|---|---|---|---|---|---|---|

### 1.3 黑名单与信号质量（`intelligent_agent_state.json`）

- 黑名单几乎覆盖所有 Grid 币种：DOGE/ETH/XRP/POL/DOT/LINK/ADA/AVAX/NEAR，以及多个 trend/scalping 币种——**系统在"逐币试错→亏损→拉黑"循环**。
- `strategy_pause.correlation_risk`：连续亏损 8 次触发暂停（总 PnL=-0.21）。
- `decision_stats`：1900 次审计 → 批准 167（8.8%）、拒绝 1163（61%）、降额 423、延迟 147。**六成信号是噪音**，信号发生器在大量生产"会被拒绝的废信号"。

### 1.4 结论：问题不在工程，在 alpha 与频率

系统已具备：幂等下单、条件单管理、熔断器（`circuit_breaker_v2`）、风控门（`strategy_risk`/`global_risk`）、凯利仓位、regime 检测、组合优化、VAR/压力测试、反针对等——**企业级"外壳"齐全**。

但"内核"策略在当前资金规模下：
1. **频率过高**（332 笔/天），单笔利润远小于磨损成本；
2. **缺乏有效 regime 门控**（`grid_trend_direction` 几乎全为 0/sideways，趋势过滤没有实际输入）；
3. **趋势策略"检测强、下单弱"**（`trend_detect_confidence` 0.7–0.9 但 7 天仅 1 信号）。

## 2. 核心判断与推荐方向

**一句话：砍掉 90% 的无效成交，把资金集中到"有正期望、有 regime 保护"的少数交易上。**

推荐主线（数据驱动）：
1. **趋势跟踪为主引擎**（Trend 检测置信度高、盈利结构健康、低换手，符合小资金"等待+一次性吃波段"的特性）。
2. **选择性均值回归为辅**（Grid/Scalping 只在震荡 regime 且符号正期望时启用，彻底砍掉磨损单）。
3. **资金费率套利为增厚**（`arbitrage` 已配置 funding/basis，正期望且与趋势负相关，用于对冲与分散）。
4. **正期望符号白名单**取代"全量→拉黑"的试错。

放弃：无门控的密集网格、martingale、动量轮动（`momentum_rotation`）、布林回归（`bollinger_mean_reversion`）——当前资金下它们只会增加磨损与相关亏损。

## 3. 设计原则

1. **生存优先**：任何单日/单周亏损触及阈值即全局降频或停机，绝不追求收益率而牺牲本金。
2. **质量优先于数量**：宁可一天 0 单，不可一天 300 笔磨损单。
3. **regime 门控一切**：无明确趋势/震荡判定的信号一律不发。
4. **正期望驱动白名单**：只交易"历史 7d/30d 盈亏 > 0 且 win_rate 或 profit factor 达标"的符号，动态重排，负期望立即摘牌。
5. **小资金专属约束**：硬性单笔风险上限、单符号集中度上限、无 martingale、最小名义值校验（已 `min_notional_usd=3.0`）。
6. **可回滚**：所有参数改动触发 30 分钟验证，PnL 回撤 >10% 或胜率回撤 >20% 自动回滚（沿用现有机制）。

## 4. 目标架构（分层）

```
┌─────────────────────────────────────────────────────────┐
│ L0 市场状态 / Regime 总门控（ADX + 波动率 + 市场结构）      │
│    - 趋势 regime：只允许 trend / 资金费率套利               │
│    - 震荡 regime：只允许 选择性均值回归（白名单内）          │
│    - 高波动/黑天鹅：全部降频或只平仓                         │
└─────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────┐
│ L1 正期望符号白名单（每 6h 重排，7d/30d 表现驱动）           │
└─────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────┐
│ L2 策略引擎（Trend 主 / Reversion 辅 / Funding 套利）       │
└─────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────┐
│ L3 信号质量门槛（多周期确认 + 体积确认 + regime 过滤）       │
└─────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────┐
│ L4 风险门（strategy_risk / global_risk / circuit_breaker）│
└─────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────┐
│ L5 执行（幂等下单 / 条件单止损止盈 / 熔断回退）              │
└─────────────────────────────────────────────────────────┘
```

## 5. 策略层设计

### 5.1 L0 Regime 总门控（最高优先级，先于一切信号）

现有系统已有 ADX、`market_structure`、`grid_trend_direction/strength` 等检测，但**没有作为硬门控**。本方案将其升级为"总开关"：

| regime | 判定 | 允许动作 |
|---|---|---|
| 趋势 | ADX > 25 且 1H 方向一致 | trend 开仓/加仓；funding 套利 |
| 震荡 | ADX < 20 且 ATR < 均值 | 白名单内 Grid/Scalping 均值回归 |
| 高波动 | ATR > 2x 均值 或 黑天鹅触发 | 全部降 50% 仓位或只平仓 |
| 低波动 | ATR < 0.5x 均值 | 仅 Scalping，Grid 暂停 |

**落地**：在 `services/strategy_coordinator.py` 或 `core/strategy_engine.py` 增加一个 `RegimeGate`，在任何策略发出信号前先查询 regime；不匹配直接丢弃（不进入审计，减少 61% 废信号）。

### 5.2 L2a 趋势核心引擎（主）

基于现有 `strategies/trend_strategy.py` 与 `_trend_base.py`，复用已配置的 4H/1H/15m 多周期确认、ATR/吊灯止损、盈亏比目标。改动方向：

- **解锁信号生成**：当前"检测强、下单弱"，需排查为何 `trend_signal_generated_total` 仅 1。重点不是改检测，而是把 `min_signal_quality`（已学 0.15）与 regime 门控对齐，让高质量趋势信号能真正过审。
- **严格单边**：`max_concurrent_positions=1`（已配置），单币种单方向，避免多空互搏。
- **盈亏比 ≥ 1.5:1**：`take_profit_pct`（4%–8%）≥ `2×stop_loss_pct`（2%）。当前 `max_stop_loss_pct=0.02`、TP 0.04–0.08，符合。
- **回撤保护**：启用 `trailing_stop` 与 `chandelier_exit`（已配置）。

### 5.3 L2b 选择性均值回归（辅，仅震荡 regime）

基于 `strategies/grid_strategy.py` / `scalping_strategy.py`，但加三道硬约束：

1. **仅白名单符号**（5.5 节），负期望符号一律不发。
2. **最小间距 ≥ 3x 双边费率**（现有约束，保留）并叠加 **7d 单符号正期望校验**——避免 SUI/UNI 这类"密集但亏损"的网格重建。
3. **严格降频**：Grid 目标 ≤ 20 笔/日（当前 332 笔/日的 6%），Scalping ≤ 5 笔/日；把 `min_signal_interval`、`signal_cooldown` 调高。

**关键取舍**：Grid 的"价值"在于震荡区间反复吃差价，但当前它成了磨损机器。方案将其降级为"震荡 regime 下的辅助"，且只在能证明正期望的 1–2 个符号（当前仅 OP）上运行。

### 5.4 L2c 资金费率套利（增厚 + 分散）

基于 `strategies/arbitrage_strategy.py`（funding/basis/correlation 已配置，`min_net_profit_pct=0.0008`）。作用：
- 正期望（funding 由市场付给持仓方向），且与趋势/均值回归**负相关**（`correlation_matrix` 中 trend↔arbitrage 低相关），用于降低组合集中度（当前 0.816）。

### 5.5 正期望符号白名单（替代"全量→拉黑"）

新增 `SymbolWhitelist`（或扩展 `intelligent_agent_state` 的 blacklist 逻辑为双向）：

- **入榜**：`7d pnl > 0` 且（`win_rate > 40%` 或 `profit_factor > 1.2`）且 交易数 ≥ 5。
- **摘牌**：`7d pnl < 0` 或 连续 5 亏损，或 30d 期望转负。
- **重排周期**：6h（与现有学习周期一致）。
- 当前数据下白名单初始候选：**OP**（46 笔 +0.107）为唯一明确达标项；SOL/SUI 待观察，UNI 直接排除。

> 效果：从"20 个币种跑网格、逐个拉黑"，收敛为"1–3 个正期望符号 + 趋势机会"，交易频率与磨损同步下降。

## 6. 信号质量门槛（对齐 L3）

沿用 `signal_generation` 现有规则，但收紧：

| 项 | 现值 | 建议 |
|---|---|---|
| `min_quality_score` | 0.4 | 0.45（趋势）/ 0.5（网格，已 memory 提至 0.5） |
| 多周期确认 | 2 规则 | 保持，且强制 regime 门控优先 |
| 体积确认 | on | 保持 |
| 同币种冷却 | 5s | 提升至 30s（网格） |
| 每日单币种上限 | 4（`max_daily_trades_per_symbol`） | 网格降至 3，趋势不受限 |

**核心目标**：让 `decision_stats.rejected` 从 61% 降到 < 30%——不是靠放水，而是靠"源头少发废信号"，让审计真正聚焦少数高质量信号。

## 7. 仓位与资金管理（小账户专属）

现有 `trading.risk_per_trade=0.015`（1.5%）、`daily_max_loss=0.03`（3%）、`max_drawdown=0.25`（25%）、`adaptive_kelly.max_kelly_fraction=0.25` 已较稳健，本方案只做 4 处加固：

1. **硬性单笔名义值下限/上限**：每笔风险 ≤ 1.5% 权益（≈0.66 USDT），单笔名义值受 `min_notional_usd=3.0` 与 `max_symbol_position_ratio` 双重约束；开仓前必查 `quantity > 0`（现有约束）。
2. **单符号集中度上限**：`symbol_allocation.max_symbol_weight=0.15`（保持），趋势单边最多 1 仓，防止单一爆仓击穿小账户。
3. **凯利分数继续打 25% 折**，且叠加 `kelly_dd_*` 回撤衰减（已配置），盈利后不急于放大。
4. **无 martingale**：`grid.martingale_layers=0`（已配置），坚决不加倍补仓。

## 8. 风控体系（对齐，不做加法）

现有 `risk/` 已覆盖：`circuit_breaker_v2`（熔断）、`strategy_risk`（L1 预检）、`global_risk`（全局）、`correlation_risk`（相关）、`black_swan_protection`（黑天鹅）、`risk_budget_engine`（预算）。本方案对齐 3 点：

1. **关单信号豁免**：风控门对 reduce_only/平仓信号跳过仓位与杠杆检查（已 memory 固化，保持）。
2. **日亏损硬停**：`daily_max_loss=3%` 触发当日停机，`max_drawdown=25%` 触发清仓。建议新增**周亏损熔断**（周亏 >6% 停机 24h），避免连续小亏叠加。
3. **网络/限流熔断**：保持"网络断连熔断自动复位 + 关键 API 路径绕过延迟熔断"（已 memory 固化）。

## 9. 监控与熔断（保持 + 补一处）

- 保持 `monitoring/`（性能监控、健康评分、告警）与端到端延迟追踪（>500ms 跳过非关键检查）。
- **补一处**：增加"磨损率"监控——`磨损单占比 = |pnl| < 1×双边费率 的笔数 / 总笔数`。阈值 >50% 时自动提高网格间距/停网格，从数据上直接止血，而不是等黑名单事后拉黑。

## 11. 分阶段落地与验收/回滚

| 阶段 | 内容 | 验收标准 | 回滚条件 |
|---|---|---|---|
| P0（止血） | 立即停掉负期望 Grid 符号（UNI 等）、停 `correlation_risk` 相关亏损组合 | 日亏损转正，磨损单占比下降 | — |
| P1（门控+白名单） | 上 `RegimeGate` + `SymbolWhitelist` | 审计拒绝率 < 40%，交易频率降 >60% | 回撤 >10% 自动回滚 |
| P2（趋势解锁） | 让趋势信号真正过审 | 趋势 7d 交易 ≥ 3 笔且 profit factor ≥ 1.5 | 连续 3 笔趋势亏损则暂停 |
| P3（降频网格） | Grid 限白名单 + 降频 + 磨损率监控 | 磨损单占比 < 50%，Grid 7d profit factor > 1.1 | 回滚网格参数 |
| P4（套利增厚） | funding/basis 套利小仓位试运行 | 套利 7d 正期望，与趋势负相关成立 | 单日套利亏 >0.5 USDT 停 |

每阶段 30 分钟参数验证（沿用现有机制），`PnL 回撤>10% 或胜率回撤>20%` 自动回滚。

## 12. 现实收益预期与风险声明（诚实）

- **不要相信 `capital_growth_plan.json` 的"30 天 +82%→80 USDT"**：其 Monte Carlo `success_rate_500` 仅 12.3%，是典型的过度乐观目标。
- 在 44 USDT 账户上，可持续的正期望策略约为 **月 3%–8%**（1.3–3.5 USDT/月），对应年化 40%–150%（小账户复利高但绝对额小）。
- **收益的天花板是资金规模，不是策略数量**。当前最该做的不是"找更多策略"，而是"把唯一赚钱的 OP 类机会做精、把亏损的磨损单砍掉"。
- **风险声明**：本方案不能保证盈利；加密合约交易存在本金亏损风险，杠杆最大 5x 时单次不利波动即可吃掉多日利润。所有数字基于历史回看，不代表未来。
